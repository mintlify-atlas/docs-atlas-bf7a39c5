---
title: "Create your first mapper"
description: "Define your first Mapperly mapper and generate mapping code at build time."
---

Mapperly generates mapping implementations at build time from partial method signatures you define. There is no reflection and no runtime overhead — the output is plain, readable C# code.

<Steps>
  <Step title="Define your source and target types">
    Start with the classes you want to map between. In this example, a `Car` domain object maps to a `CarDto` transfer object:

    ```csharp Car.cs
    public class Car
    {
        public string Name { get; set; } = string.Empty;
        public int NumberOfSeats { get; set; }
        public CarColor Color { get; set; }
        public Manufacturer? Manufacturer { get; set; }
    }

    public enum CarColor { Black = 1, Blue = 2, White = 3 }

    public class Manufacturer
    {
        public Manufacturer(int id, string name) { Id = id; Name = name; }
        public int Id { get; }
        public string Name { get; }
    }
    ```

    ```csharp CarDto.cs
    public class CarDto
    {
        public string Name { get; set; } = string.Empty;
        public int NumberOfSeats { get; set; }
        public CarColorDto Color { get; set; }
        public ManufacturerDto? Manufacturer { get; set; }
    }

    public enum CarColorDto { Black = 1, Blue = 2, White = 3 }

    public class ManufacturerDto
    {
        public ManufacturerDto(int id, string name) { Id = id; Name = name; }
        public int Id { get; }
        public string Name { get; }
    }
    ```
  </Step>

  <Step title="Declare the mapper">
    Create a `partial` class, apply the `[Mapper]` attribute, and declare your mapping methods as `partial` — without a body. Mapperly fills in the implementations at build time.

    ```csharp CarMapper.cs
    using Riok.Mapperly.Abstractions;

    [Mapper]
    public partial class CarMapper
    {
        public partial CarDto CarToCarDto(Car car);
    }
    ```

    Mapperly matches properties by name and type automatically. No configuration is needed for straightforward mappings.

    <Note>
      The mapper class must be `partial`. Mapperly adds the generated method bodies to the same partial class during compilation.
    </Note>
  </Step>

  <Step title="Use the mapper">
    Instantiate the mapper and call your mapping method like any other method:

    ```csharp Program.cs
    var mapper = new CarMapper();

    var car = new Car
    {
        Name = "my car",
        NumberOfSeats = 5,
        Color = CarColor.Blue,
        Manufacturer = new Manufacturer(1, "best manufacturer"),
    };

    var dto = mapper.CarToCarDto(car);
    // dto.Name == "my car"
    // dto.NumberOfSeats == 5
    ```
  </Step>

  <Step title="Inspect the generated code">
    Mapperly emits a second partial class file during compilation. For the mapper above, the generated output looks like this:

    ```csharp CarMapper.g.cs (generated)
    // <auto-generated />
    public partial class CarMapper
    {
        public partial CarDto CarToCarDto(Car car)
        {
            var target = new CarDto();
            target.Name = car.Name;
            target.NumberOfSeats = car.NumberOfSeats;
            target.Color = (CarColorDto)car.Color;
            if (car.Manufacturer != null)
            {
                target.Manufacturer = MapToManufacturerDto(car.Manufacturer);
            }
            return target;
        }

        private ManufacturerDto MapToManufacturerDto(Manufacturer source)
        {
            var target = new ManufacturerDto(source.Id, source.Name);
            return target;
        }
    }
    ```

    The generated code is plain C# with no reflection. You can read and debug it like any other code.

    <Tip>
      To view the generated source in your IDE, enable generated source output in your `.csproj`. See the [generated source configuration](/configuration/mapper) for details.
    </Tip>
  </Step>
</Steps>

## Static mapper variant

If you prefer a static API, declare the mapper class as `static partial`:

```csharp
using Riok.Mapperly.Abstractions;

[Mapper]
public static partial class CarMapper
{
    public static partial CarDto CarToCarDto(Car car);
}
```

Usage:

```csharp
var dto = CarMapper.CarToCarDto(car);
```

The [sample project](https://github.com/riok/mapperly/tree/main/samples/Riok.Mapperly.Sample) uses a static mapper to demonstrate this pattern.

## Compile-time safety

Mapperly emits warnings during compilation for unmapped members. If a property on the target type has no matching source property and no explicit configuration, you will see a diagnostic warning at build time — before your code runs.

This means mapping gaps are caught during development, not at runtime.

## Common issues

<AccordionGroup>
  <Accordion title="Mapperly does not work when I use another source generator">
    Chaining source generators is not supported by Roslyn. Mapperly cannot consume types emitted by other source generators in the same compilation.
  </Accordion>

  <Accordion title="I updated the Mapperly version but the generated code looks the same">
    Restart your IDE to force it to load the new version of Mapperly. This is a known IDE bug.
  </Accordion>

  <Accordion title='The IDE shows "[Mapper method] must have an implementation part because it has accessibility modifiers"'>
    Make sure your project meets the [requirements](/getting-started/installation#requirements). Try rebuilding the solution or restarting the IDE. This is a known IDE bug.
  </Accordion>

  <Accordion title="My advanced use case needs lots of configuration or isn't supported">
    You can mix generated mappings with [user-implemented mappings](/configuration/user-implemented-methods). Write the complex mapping manually and let Mapperly handle the rest.
  </Accordion>
</AccordionGroup>
